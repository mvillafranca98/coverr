# Coverr: standards status

Written by the dev-standards kickoff skill and kept current by the audit skill.

Status values:
- **TODO:** not checked yet, or couldn't be checked this time (say why)
- **PASS:** met, with evidence
- **FAIL:** the main requirement isn't met
- **PARTIAL:** the main requirement is met, but a secondary part isn't
- **MANUAL:** only you can do or verify it
- **N/A:** doesn't apply, or the thing it governs doesn't exist yet (say which)

## Data inventory
Every service that receives user data, including hosting, database and auth providers. It must match the privacy policy (LEG-02).

| Service | Used for | Data it receives | In privacy policy |
|---|---|---|---|
| Cloudflare Workers | Hosting and request handling | All request data, including IPs used as rate-limit keys | yes |
| Cloudflare D1 | Application database | Buyer name, email, phone; attendee names and notes; order and check-in records; band and member details | yes |
| Cloudflare R2 | Payment proof storage | Bank confirmation screenshots. These contain a **third party's** full account number, name and sometimes email — the payer is often not the attendee | yes |
| Anthropic | Extracting fields from payment proofs | The proof image itself, and therefore the banking details in it | yes |
| Resend | Transactional email | Buyer email addresses, ticket contents, band contact address | yes |
| WhatsApp (wa.me) | Admin click-to-chat link on the order page (`src/views/admin/order.tsx:115`) | A buyer's phone number, only when an admin clicks it. Nothing is sent server-side | yes |
